# إصدار تحديث لبرنامج الكاشير (ويندوز) بأمان

هذا الدليل يشرح كيف تنشر إصداراً جديداً، وكيف تستلمه أجهزة الكاشير بنفسها، وكيف نحمي بيانات الزبائن في كل مرة.

## أين توجد البيانات

| البيانات | مكانها | هل يلمسها التحديث؟ |
|---|---|---|
| المبيعات، الإيصالات، المناوبات، المنيو، الطاولات، الكاشيرات | قاعدة بيانات Supabase | لا |
| مبيعات ومصاريف أوفلاين لم تُرفع بعد، نسخة المنيو، أرقام الإيصالات المحجوزة، ربط الخانة | `%APPDATA%\com.example\menu_web_v1` على الجهاز | لا |
| ملفات البرنامج | `%LOCALAPPDATA%\Programs\CafePOS` | نعم، فقط هذه |

> ⚠️ لا تغيّر `CompanyName` ولا `ProductName` في `windows/runner/Runner.rc`. ويندوز يحفظ بيانات الجهاز في مجلد بهذين الاسمين؛ تغييرهما يجعل الإصدار الجديد يبحث في مجلد فارغ. يوجد اختبار يمنع ذلك.

## كيف يستلم الجهاز التحديث (تلقائياً)

1. كل 30 دقيقة (وعند التشغيل) يقرأ البرنامج `latest.json` من صفحة الإصدارات.
2. إذا كان الإصدار أحدث، ينزّل المثبّت بالخلفية ويتحقق من بصمته (SHA-256). أي ملف مختلف يُحذف ولا يُشغَّل.
3. تظهر بطاقة "التحديث جاهز" في **شاشة تسجيل دخول الكاشير فقط**.
4. عند الضغط على "ثبّت الآن" يتأكد البرنامج أن:
   - لا يوجد كاشير مسجَّل الدخول؛
   - لا توجد مبيعات أو مصاريف تنتظر الرفع، ولا مرفوضة؛
   - السيرفر يملك **كل** إيصال ومصروف رفعه هذا الجهاز خلال 60 يوماً، بنفس العدد ونفس المجموع.
   إذا فشل أي شرط لا يُثبَّت التحديث وتظهر رسالة بالسبب.
5. ينسخ بيانات الجهاز إلى `%APPDATA%\com.example\menu_web_v1\backups\<التاريخ>` (يحتفظ بآخر 3 نسخ).
6. يشغّل المثبّت بصمت، يُغلق البرنامج، يتحدّث، ثم يفتح من جديد.
7. عند أول تشغيل بعد التحديث يطابق المبيعات مع السيرفر مرة أخرى ويعرض النتيجة.

## خطوات نشر إصدار جديد

1. **إذا كان في الإصدار تغيير على قاعدة البيانات** (ملف جديد في `supabase/migrations`):
   1. خذ نسخة احتياطية: GitHub → Actions → **Database backup** → Run workflow، وانتظر نجاحها. (ويمكن أيضاً زر "Download all logs" في شاشة المطوّر.)
   2. تأكد أن الاختبارات تنجح على نسخة محلية: `tool/test_db.sh`.
   3. طبّق الـ migration على Supabase **قبل** نشر البرنامج.
   4. تأكد أن الأجهزة القديمة ما زالت تعمل (بيع واحد على الأقل).
2. ارفع رقم الإصدار في `pubspec.yaml`، مثلاً `version: 1.2.0+3`.
3. ادمج التغييرات في `main`.
4. أنشئ وسماً بنفس الرقم وارفعه: `git tag v1.2.0 && git push origin v1.2.0`.
5. GitHub Actions → **Windows release** يبني البرنامج، يشغّل الاختبارات، يصنع المثبّت و`latest.json` وينشرهما.
6. خلال 30 دقيقة تظهر بطاقة التحديث في الأجهزة.
7. من شاشة المطوّر → "Tills and app versions" تابع إصدار كل جهاز.

## قواعد تغيير قاعدة البيانات

1. **نسخة احتياطية قبل أي تغيير** (الخطوة 1.1 أعلاه).
2. **أضف أولاً، احذف لاحقاً**: الإصدار الأول يضيف الجديد ويُبقي القديم، حتى تعمل الأجهزة القديمة والجديدة معاً. الحذف يكون في إصدار لاحق، فقط بعد أن تُظهر شاشة المطوّر أن كل الأجهزة على الإصدار الجديد.
3. **الترتيب**: قاعدة البيانات أولاً، ثم البرنامج.
4. **اختبار قبل التطبيق**: كل migration له اختبار SQL في `supabase/tests` ويُشغَّل عبر `tool/test_db.sh`.
5. **خطة تراجع**: كل migration له ملف في `supabase/rollbacks/<الاسم>.down.sql`، و`tool/test_db.sh` يتأكد أنه يتراجع وأن الـ migration يُطبَّق من جديد بعده.
6. **أقل إصدار مسموح**: عندما يجب أن تتوقف الإصدارات القديمة، ضع الرقم في شاشة المطوّر → "Minimum version". الأجهزة الأقدم لا تسمح بتسجيل دخول الكاشير حتى تُحدَّث.

## عند حدوث مشكلة

- **خلل في البرنامج الجديد**: انشر إصداراً جديداً برقم أعلى يحتوي الإصلاح (أو بالكود القديم). قاعدة البيانات متوافقة معه بفضل قاعدة "أضف أولاً".
- **خلل في قاعدة البيانات**: طبّق ملف التراجع من `supabase/rollbacks`، أو استرجع النسخة الاحتياطية:
  ```
  gpg --decrypt backup-<التاريخ>.sql.gz.gpg | gunzip | psql "<connection string>"
  ```
- **بيانات جهاز**: النسخ الاحتياطية في `%APPDATA%\com.example\menu_web_v1\backups`. أغلق البرنامج وانسخ محتوى النسخة إلى `%APPDATA%\com.example\menu_web_v1`.

## إعداد لمرة واحدة

- GitHub → Settings → Secrets and variables → Actions:
  - `SUPABASE_DB_URL`: من Supabase → Connect → Session pooler (مع كلمة سر قاعدة البيانات).
  - `BACKUP_PASSPHRASE`: كلمة سر طويلة لتشفير النسخ الاحتياطية. احفظها في مكان آمن؛ بدونها لا يمكن فتح النسخ.
- على كل جهاز كاشير: ثبّت `CafePOS-setup-<الإصدار>.exe` من صفحة الإصدارات مرة واحدة (بدل نسخ ملف exe). بعدها تأتي التحديثات وحدها.
