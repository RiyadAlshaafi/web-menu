## Better admin login for the offline version

What happens today: email + complex password, ✅ **no lockout** (`app_database_local.dart:140-148`), and "remember" keeps the admin signed in forever with no idle lock. Recovery needs the seller. Hashing is plain SHA-256 in an unencrypted file.

Recommended design, in order:

| Step | What | Size |
|---|---|---|
| 1 | Lockout + backoff on admin password (reuse cashier PIN logic), constant-time compare | small |
| 2 | Auto-lock after 10 min idle → quick **6-digit admin PIN** unlock; "remember" expires end of day | small |
| 3 | Offline setup: owner name + passphrase (any chars, 10+), email optional | small |
| 4 | 8 one-time **recovery codes** printed at setup → owner can reset without the seller | small |
| 5 | PBKDF2/Argon2 + device secret (DPAPI), hash in isolate, auto-upgrade old hashes | small |
| 6 | One lock screen: staff tiles + PIN pad, roles cashier / manager / owner | major |

## Making the system easier to read and understand (code)

- `lib/data/app_database.dart` is **2,520 lines in one class**. Split it into `part` files (auth / catalog / sales / realtime), the way `cafe_store_*` already is.
- The Arabic dish name is called `nameIt`. Rename the Dart field to `nameAr` and keep the DB column.
- Models are mutable and shared between the store and the DB. Make `Payment`, `CashShift` and `OrderLine` immutable first.
- Every live update reloads about 12 tables. Reload only the table that changed. `app_database.dart:760-792`
- Whole screens rebuild on every store change. Use `context.select`.
- The main cashier screens have no widget tests. Add 3: pay a takeout sale, send a table cart, refuse an empty register count.
